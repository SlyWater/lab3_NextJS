# Лабораторная работа 3

Вариант 7. Next.js, JavaScript, Pages Router.

## Запуск

```powershell
npm ci
npm run dev
```

Для Яндекс Карты задайте NEXT_PUBLIC_YANDEX_MAPS_API_KEY в окружении или локальном .env.local. После изменения ключа production-сборку нужно повторить.

```powershell
npm run build
npm start
```

## Этапы по методичке

1. Подготовка Next.js и страница /content с картой Пензы через react-yandex-maps. Главная первого этапа с фамилиями и группой затем заменяется на Petto по методичке.
2. Главная заменена Petto: animals.json, слайдер, имя через prompt и localStorage, письмо владельцу по нажатию на карточку, выход. Страница /communities показывает сообщества текущего пользователя и позволяет создать сообщество с названием, описанием и аватаркой. Создатель входит в своё сообщество. Список изначально пустой; данные сохраняются в текущем браузере отдельно по имени. Это не серверная база пользователей.
3. Публикация на Vercel — заключительный этап работы. Порядок развёртывания приведён ниже.

Теоретические примеры API времени и загрузки файлов, варианты 1–6 и 8–9 и база данных не включены.

По последующему запросу добавлены стили карточки из листинга 8 (фото на весь слайд, белый текст поверх фото) и минимальное оформление форм, кнопок и карточек сообществ. Фотография позиционируется внутри слайда, а не относительно окна.

legacy-peer-deps в .npmrc нужен из-за старых peer-зависимостей react-yandex-maps. prop-types нужен react-awesome-slider.

Открывайте http://localhost:3000 в обычном Chrome или Edge с поддержкой prompt. Интернет нужен для загрузки Яндекс Карты; объявления и сообщества хранятся локально.

## Публикация на Vercel

В GitHub загружается отдельный репозиторий из каталога `lab_3/project`, где уже находится `.git`. Родительский каталог с другими лабораторными и отчётами загружать не нужно. `.gitignore` исключает зависимости, сборку, локальные инструкции и файлы окружения.

1. Создайте репозиторий GitHub и отправьте в него исходники этого проекта.
2. В Vercel выберите **Add New → Project** и импортируйте репозиторий.
3. Укажите **Framework Preset: Next.js**, **Root Directory: .**, **Build Command: npm run build**. Остальные настройки сборки оставьте стандартными. Параметр `legacy-peer-deps=true` берётся из `.npmrc`.
4. Перед сборкой добавьте `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` в окружение **Production**. Для проверки предварительных развёртываний добавьте её также в **Preview**. Значение задаётся в настройках Vercel и не добавляется в Git.
5. Выполните **Deploy**. После изменения переменной окружения выполните новое развёртывание: публичный ключ карты включается в JavaScript во время сборки.
6. Откройте публичный адрес и проверьте `/`, `/content`, `/communities`: ввод имени, переключение животных, карту, создание сообщества с аватаркой и восстановление после перезагрузки. На новом домене localStorage первоначально пустой.
7. Внесите адрес репозитория, адрес сайта и скриншот успешного развёртывания в отчёт.

Используется браузерный ключ Яндекс Карт: его значение доступно посетителям сайта. Если для ключа настроены ограничения по доменам, опубликованный домен должен быть разрешён владельцем ключа.

Документация: [импорт Git-репозиториев в Vercel](https://vercel.com/docs/git), [переменные окружения Vercel](https://vercel.com/docs/environment-variables), [публичные переменные Next.js](https://nextjs.org/docs/pages/guides/environment-variables).
